只支持 Linux，systemd 与 OpenRC 都行。不提供 Docker 镜像，理由见 [Docker 部署](/install/docker)。

## 单台安装

在面板 **节点 → 添加** 填一个名字，再点这个节点旁边的下载按钮，复制生成的命令：

```bash
curl -fsSL https://hub.example.com/install.sh | sh -s -- \
  --server https://hub.example.com --token <token>
```

以 root 在目标主机执行，几秒钟后节点就会在面板里亮起来。软路由、PVE 宿主机这类转发流量的机器，
装之前先看[流量统计](/config/traffic)页的「哪些网卡计入」一节。

二进制由 hub 转发（`<hub>/agent/<arch>`），节点不需要能连上 GitHub——能连上 hub 就能装，
IPv6-only 或者出不去的机器也一样。

## 批量注册

**节点 → 批量添加**开一个一小时的注册窗口。期间下面这条命令在任意机器上跑一次，那台机器就会带着
自己的 hostname 出现在列表里，各自拿到各自的 token：

```bash
curl -fsSL https://hub.example.com/install.sh | sh -s -- \
  --server https://hub.example.com --register <key>
```

弹窗里的上报间隔和统计的网卡对这一批机器一起生效，改了命令跟着变。

命令里没有任何一台机器的凭证，可以直接进 `for` 循环、ansible 或者开机脚本。末尾加 `--name <名字>`
可以自己指定节点名，循环里用 ssh 的主机别名就不用装完再一台台改：

```bash
# 逐台执行，节点按 ssh 别名命名；连不上或装失败的机器单独打一行，最后只重跑那几台
for h in node1 node2 node3; do
  ssh -o BatchMode=yes "$h" "curl -fsSL https://hub.example.com/install.sh |
    sh -s -- --server https://hub.example.com --register <key> --name $h" \
    || echo "!! $h 失败" >&2
done
```

远程命令用双引号，`$h` 才会在本机展开成别名再发过去。`--name` 只在新建节点时生效，已经注册过的机器
重跑不会改名，改名在面板里改。

ssh 登录的不是 root 时，把 `| sh` 换成 `| sudo sh`。并行跑也行（ansible、pssh、`xargs -P`）：hub 同时
转发 4 份二进制，其余排队，排不上的由脚本自动重试，几百台同时发起也能装完。

窗口到点自动失效，一个窗口最多注册 100 台。重跑同一条命令不会重复添加：机器上已有的 token 只要还对应着
节点就直接沿用，窗口关了也一样。节点在面板里删掉了，旧 token 就不再算数，要开着窗口重跑，那台机器会注册
成一个新节点。

装好之后升级不要再跑这条注册命令，用下面[升级](#升级)一节的 `--upgrade`：更新页的**复制名单**一行一台
列出待升级的节点，存成 `hosts.txt`，进同样的循环。注册命令只管新机器，拿它升级的话，哪台机器的 token
丢了就会悄悄多出一个节点。

<Note>
  key 泄露的影响范围：在窗口剩下的时间里最多建 100 个节点，每个只能上报它自己那一个节点，
  读不到已有节点的数据，也改不了设置。代价是面板里多出一批垃圾节点，关掉窗口删掉即可，
  已经装好的机器不受影响。
</Note>

## 升级

面板左侧的**更新**页列出 hub 和 agent 的版本情况：有新版本时导航上那一项会带一个小圆点，点进去能看到按版本分组的待升级节点，以及这条命令：

```bash
curl -fsSL https://hub.example.com/install.sh | sh -s -- --upgrade
```

它用机器上已有的凭证和设置重装二进制：不需要 token，也不会新建节点，`--interval` 和 `--iface`
照旧沿用。没装过 agent 的机器会直接报错，不会变成一个新节点。

命令对每台机器都一样，所以可以直接进循环，并行同样可以。待升级的机器不用自己数：更新页的
**复制名单**给出一行一台的节点名。批量注册时用 `--name` 按 ssh 别名命名过的，这份名单直接就是主机列表；
没有的话把名字换成 ssh 连得上的地址。存成 `hosts.txt`：

```bash
# 逐台升级 hosts.txt 里的机器；失败的单独打一行，原因在它上面那几行输出里
for h in $(cat hosts.txt); do
  ssh -o BatchMode=yes "$h" \
    'curl -fsSL https://hub.example.com/install.sh | sh -s -- --upgrade' \
    || echo "!! $h 失败" >&2
done
```

下载失败或下回来的不是可执行文件（比如 GitHub 代理回了一张错误页）时，脚本在停掉旧 agent 之前就退出，
那台机器照旧运行原来的版本。升级完回到**更新**页，待升级的名单会随着节点重连逐个消失。

hub 用明文地址（`http://`）的，命令末尾照样要加 `--insecure`。

<Note>
  没有自动更新，这是故意的：hub 能向所有节点推二进制，就等于 hub 一旦被拿下，所有节点同时被拿下。
  升级由你发起，hub 没有推送通道。
</Note>

## 换 token

点节点旁边的下载按钮打开安装弹窗，在**换发凭证**一栏点「换发」。旧 token 立刻失效，包括已经连着的那条连接：hub 会把这个节点踢下线，
它拿旧 token 重连会吃到 401。

换发之后用这个节点自己的安装命令重装，不要重跑批量注册命令：批量命令认不出换发前的 token，会另建一个
节点，原节点连同它的历史数据留在面板里一直显示离线。

安装命令随时可以再看一次，token 不是只显示一次。
