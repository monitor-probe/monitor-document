agent 只支持 Linux，x86_64 与 aarch64，systemd 与 OpenRC 都可以。

## 单台安装

**节点**页点「添加节点」填一个名字，再点这一行的安装按钮（下载图标），复制弹窗里的命令：

```bash
curl -fsSL https://hub.example.com/install.sh | sh -s -- \
  --server https://hub.example.com --token <token>
```

以 root 在被监控的机器上执行，几秒后节点在面板里上线。安装命令随时可以再打开，token 不是只显示一次。

软路由、PVE 宿主机这类转发流量的机器，装之前先看[流量统计](/config/traffic#哪些网卡计入)。

二进制由 hub 转发（`<hub>/agent/<arch>`），机器能连上 hub 就能装，不需要能访问 GitHub。

### 安装选项

弹窗里的**安装选项**改了，下面的命令随之变化：

| 选项 | 命令参数 | 说明 |
|---|---|---|
| 上报间隔 | `--interval <秒>` | 1–3600，默认 1 |
| 指定统计的网卡 | `--iface <列表>` | 见[流量统计](/config/traffic#转发流量的机器要手动指定) |

两项都记在机器上，以后重跑安装或升级时不写就沿用。

## 批量注册

**节点**页点「批量添加」，开一个一小时的注册窗口。窗口开着时，这条命令在任意机器上执行一次，那台
机器就以自己的 hostname 出现在节点列表里，各自拿到各自的 token：

```bash
curl -fsSL https://hub.example.com/install.sh | sh -s -- \
  --server https://hub.example.com --register <key>
```

- 命令里没有任何一台机器的凭证，所有机器共用同一条。怎么发到几十上百台机器上，见
  [批量安装与升级](/install/batch)
- 末尾加 `--name <名字>` 指定节点名，只在新建节点时生效；已注册的机器重跑不会改名，改名在面板上改
- 窗口一小时后自动失效，一个窗口最多注册 100 台
- 重跑同一条命令不会重复添加：机器上已有的 token 还对应着节点，就直接沿用，窗口关了也一样。节点在
  面板上删掉后，旧 token 失效，要在窗口开着时重跑，那台机器会注册成一个新节点

装好之后升级用下面的 `--upgrade`，不要再跑注册命令：token 丢失的机器会被悄悄注册成一个新节点。

<Note>
  key 泄露的影响范围：窗口剩下的时间里最多新建 100 个节点，每个只能上报自己，读不到已有节点的数据，
  也改不了设置。关掉窗口，删掉多出来的节点即可，已装好的机器不受影响。
</Note>

## 升级

面板左侧的**更新**页列出 hub 和 agent 的版本。有新版本时导航上的「更新」带一个小圆点，页面里有按版本
分组的待升级节点，以及这条命令：

```bash
curl -fsSL https://hub.example.com/install.sh | sh -s -- --upgrade
```

以 root 在每台机器上执行一次，所有机器共用。机器多时见[批量安装与升级](/install/batch)。

- 用机器上已有的 token 和设置重装二进制，不新建节点，`--interval` 和 `--iface` 沿用
- 没装过 agent 的机器直接报错，不会变成新节点
- 下载失败、或下回来的不是可执行文件时，脚本在停掉旧 agent 之前退出，机器照旧运行原来的版本；新版装上
  后起不来的，脚本换回原来的版本并重启，同样以报错结束
- hub 地址是明文 `http://` 的，命令末尾要加 `--insecure`

<Note>
  agent 不自动更新。hub 能向所有节点推送二进制，就意味着 hub 一旦被攻破，所有节点同时失守，所以升级
  只由你在机器上发起。用 cron 在每台机器上定时跑 `--upgrade` 等于把这条通道重新搭了起来，不建议。
</Note>

## 换发 token

打开节点的安装弹窗，在**换发凭证**一栏点「换发」。旧 token 立即失效，已经连着的 agent 会被断开，拿旧
token 重连时得到 401。只在 token 可能泄露时使用。

换发后用这个节点弹窗里的新命令重装。不要跑批量注册命令：它认不出换发前的 token，会另建一个节点，
原节点连同历史数据留在面板上一直显示离线。
